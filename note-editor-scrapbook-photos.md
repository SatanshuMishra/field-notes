## Goal

Turn the plain-text Write a Note feature into a live Markdown editor with photos placed in the text, where body text wraps beside a photo on a wide screen and stacks above and below it on a narrow one. The spec is docs/specs/2026-09-20-note-editor-and-scrapbook-photos.md; its section 0 records what has shipped.

## Decisions in force

- D1 New-note drafts are keyed by date, not by session: Key by date (new-YYYY-MM-DD). Reopening a composer for the same date restores the draft behind the existing inline chip; a different date does not see it, so a note is never saved under the wrong day. At most one orphan per date. Delete all now removes the drafts folder so a deleted journal cannot resurface through a draft. The edit route keeps keying by entry id. Specified in docs/specs/2026-09-21-note-fix-wave.md ruling W1; supersedes the u3 session-key stress fix.
- D2 A short composer moves its tools into existing rows instead of dropping them: Move the tools into existing rows. Not roomy: header row becomes close, format bar, Save, with the title omitted; the header grows 31 to 36pt and the editor keeps three lines. The rail sits below the surface only when its budget reaches 72pt, otherwise it renders a 36x36 slim Add tile inside the bar. The rail is wrapped in a GlobalKey so a pick started from the slim tile survives the relayout when the system picker closes the keyboard. Ruling W3 of the fix-wave spec.
- D3 Fix wave ships through mitosis items with local holds before any pull request: Run with --no-push from feature branch docs/note-fix-wave-spec (the spec PR #140), with a Flutter acceptance wrapper that maps flutter test exit codes onto mitosis's pass, fail and inconclusive contract and treats a test that fails to compile only because its named behaviour is absent as a failure. Each held branch gets the full local suite and an independent review before its pull request opens through the PR tool.
- D4 Extend note-guards past its spec after independent review: Add the follow-up commit after the mitosis gate for note-guards has run, so the gate's revert probe is not disturbed. The items file stays as it ran; the spec document and the PR body record the extension.
- D5 Fix every review finding on its branch before any fix PR opens: Fix on-branch before PRs. Drafts: controller seals on discard and after save (seal delegates to discard), a close waits up to 2 s for restore before judging clean, sandbox overrides draftRootProvider. Preview: leading photo kept whole, photo after the kept photo ends the preview, dropped photo leaves a line break, fit judged by the photo line, prose identical to the old algorithm (5000-note differential check). Composer: showTransientToast gains a glyph parameter and rises above the keyboard. Corrupt photo: NotePhotoFigure keyed by reference; the failed lane was finished by hand with the same revert probe mitosis runs (both properties load-bearing). Bench: images warmed into ImageCache before timing and asserted painted on the first sample. Guards: calls counted per file; three more workflow paths.
- D6 A close during a draft load asks first instead of waiting: Treat loading as dirty (ec38556). ComposerGuard is byte-identical to its reviewed a9641cf form; NoteDraftController.isRestoring feeds isDirty in both connectors; a restore finishing after discard is not applied. The confirm dialog is modal, so no Save can run under it. A hung draft store still hangs discard as it did before this wave; that is pre-existing residue, not claimed fixed.
- D7 Defer u10 and the Android benchmark: Deferred by the owner: "Defer the u10 and android benchmarks. Wait for specific instructions." No further work on this thread until instructed.
- D8 Composer photos: Inline chosen; free-placement Scrapbook deferred: Owner chose Inline ("Go with in-line"). Reasons: anchored photos survive reflow at every width (phone, full-width Today, day detail, composer); the existing storage, parser, reader, float, preview and search already treat a photo as a line of the note; R2 stays intact; phone and keyboard use work with taps; and free placement can be added later as a new placement type without migrating Inline notes, while the reverse would require converting positioned photos. The scrapbook feel (tape, tilt, white print border, handwritten caption) is applied to Inline photos as a visual style.
- D9 The editor wraps text beside a photo, reversing spec rule R1 and ruling C2: Wrap inside the one field. The editor measures the paragraph at the reader's narrower column and forces each of those breaks by replacing the break character with an invisible box that fills the rest of the line, and it indents a line beside a photo on the left by making that box as wide as the photo. The drawn text stays the same length as the saved note and only whitespace is ever replaced, so caret offsets, copy and the saved text are unchanged. The measured Android hazard is a gesture recognizer on a span, not a placeholder, so the build-failing grep test keeps banning recognizers and a widget test now pins that every placeholder is an empty box. The note's photos moved inside the scrolling content, which fixes the scroll fault as a side effect. Beside a photo on the left the framework would draw the caret behind the picture, so the composer draws that caret itself.
- D10 Word and line deletes follow I4 mapping; inside a table cell they stay inside that cell: Map through sourceRangeForVisible. When the caret is in a table cell, clamp to that cell's content range (spec T2, and it matches Backspace at a separator changing nothing). Otherwise split at tables the way the input-method delta path does, so the key path and the input-method path agree and hidden table bytes are never deleted. _splitAtTables became public splitAtTables in delta_mapping.dart. Committed as df4f383.
- D11 PR 181 gestures: keyboard recall on tap uses a new required NoteTouchSelection.onRequestKeyboard: Required VoidCallback onRequestKeyboard, called on every single tap-up except checkbox toggles (commit eca798d). Sending the event through onSelectionChanged would make the assembly's spelling toolbar reopen after a tap on a misspelled caret, so the tap could no longer toggle that toolbar. An optional callback would do nothing unnoticed until wired. Required matches the widget's other callbacks, and the compiler forces every host to wire it.
- D12 PR 181 paste: moved photo lines follow the block holding the paste point in the post-paste text: The third option (commit 375b55b). It never produces overlapping replacements, and it matches _photoLinesLand's rule that photo lines must not split a text block of that result. 'Hello world\n\nNext' with 5..12 selected and a photo pasted gives 'Hello\nNext\n![p](...)'. One behaviour changed: when the pasted text itself contains a paragraph break, the photo lands after the block holding the caret, not after the last pasted block.
- D13 PR 181 overlay: the selection overlay controller keeps itself in sync with the render view: A post-frame check that runs only while handles or the toolbar are showing. It compares the selection and the layout identity and calls update() only on a change, and it schedules no frames (commit 8c277c4). Handle drags also refuse to reach or cross the other end on every platform, not only Android and Fuchsia, because RenderNoteView always places the start and end links at selection start and end (commit 5719d67).
- D14 Photo toolbar hides, not re-places, when its photo starts in the composer's bottom inset band: Reject the above slot unless the bar ends at or above surface.bottom, and have PhotoToolbarLayer drop the bar (keeping the caption field) when the figure does not overlap the surface above the inset. The engine option was out of the PR's files. Committed as a9d075f on mitosis/switch-over.
- D15 Probe harness judges photo side edits and drop targets from probe-reported block ranges, in Dart: The probe's /state blocks now carry start, end, unclosedFence, globalTop and globalBottom. The driver sends a photoCommand (control, photo ordinal, source, blocks) and gates.dart derives the allowed ranges with oracles.photoCommandRanges. Drops and drags aim at the probe-reported window coordinates of the intended boundary. This reuses the tested Dart oracle instead of reimplementing P3 in shell. Commits 7f9a164 and 90f3124 on mitosis/harness.

## Open risks

- R1 New-note draft restore never works: each composer open mints a fresh session id and looks for a draft under it, so a draft saved before a crash is written and never read back. Spec defect from the session-key stress fix; Discard already deletes the file, so any surviving draft was lost, not abandoned. Bears on c1.
- R2 Feed preview shows every photo in its first 1200 characters instead of only the first. u2 delivered the cap; u7 rewrote its test to a photo-less note asserting findsNothing; u8 restored photo rendering without restoring the cap. Bears on c1.
- R3 The photo mini-diagram always reports stacked, even where the reader floats the photo: rail and options sheet call planFloat without nextIsParagraph. Correct when u8 merged; u9 made planFloat actually float and introduced the drift. A test asserts the wrong behaviour. Bears on c1.
- R4 The Add photo tile disappears when the rail's height budget drops under 72, which includes a phone in landscape with the keyboard up. There is then no way to add a photo. A test locks this in. Bears on c1.
- R5 The format bar, and with it the Undo control, is removed entirely on short panels such as a landscape phone with the keyboard up: the exact case Undo was added for, since Android has no Ctrl-Z. Bears on c1.
- R6 An unknown or unparseable photo placement defaults to right/medium and floats, breaking the rule that StackedPhoto is the single fallback for every failure. No test covers it. Bears on c1.
- R7 A corrupt photo file floats: the resolver treats a blob as available when its row and file exist, not when it decodes. The test named corrupt or missing only exercises a missing reference. Bears on c1.
- R8 EXIF orientation is never read: PhotoIntrinsics holds width and height only. A portrait phone photo may display rotated or with swapped dimensions. Not yet checked whether the engine already reports rotated dimensions. Bears on c1.
- R9 The feed preview cuts at whitespace, and a photo line's caption and placement contain spaces, so the cut can land inside a photo token and leave a malformed line. No test covers it. Bears on c1.
- R10 Four tests assert defects rather than the spec, so a green suite locks them in: the preview photo cap, the missing Add photo tile, the stacked-only diagram and the missing format bar. Fixing each means rewriting its test first. Bears on c1.
- R11 CI never runs the golden images for a change to the float code: goldens.yml's path filter covers lib/design/** but not lib/features/notes/**. Local validation still runs them.
- R12 The benchmark's photo-layout numbers measure placeholder stubs, not real photos or the float: it was written before u8 and u9 existed. Its two keystroke numbers, which decide u10, measure the shipped editor correctly. Bears on c2.
- R13 A draft store whose future never resolves still hangs a composer's discard, because the delete queues behind the pending read; pre-existing before this wave and not fixed by it.
- R14 Benchmark numbers 3 and 5 moved 26 and 41 percent at p50 between two desktop runs at different host loads; treat them as load-sensitive when comparing with the device run. Bears on c2.
- R15 Conformance audits check the spec, not platform configuration: the macOS sandbox entitlement gap that hung Add photo passed every audit and every test. Native pickers and panels on each platform are only proven by running the app.
- R16 The in-place experiment guards photo lines against hardware-key and text-input edits on macOS, but soft-keyboard deletions on phones arrive as text input and are not yet guarded, so a phone Backspace inside a photo line could corrupt its Markdown.
- R17 The text the editor draws is no longer character for character the saved note: a space or line break that carries a wrap spacer draws as an empty placeholder box. The length is preserved and a test pins that only whitespace is ever replaced, so caret offsets, copy and the saved note are unchanged, but any future code that reads the rendered span as the note's text would be wrong.
- R18 A paragraph beside a photo on the left falls back to a stacked photo when a line cannot be broken at whitespace, which includes scripts without spaces such as Chinese and Japanese. Nothing warns the writer; the photo simply stops floating.
- R19 The phase 5 toolbar has no Centre placement, because centre does not exist in the model until phase 3. A note written now can only say left or right, and the toolbar grows a third button later.
- R20 A resolve that throws now sticks as missing until the widget remounts. MediaStoreResolver._load memoizes a missing result but not a thrown one, and the old FutureBuilder(future: resolve(id)) re-invoked resolve on every rebuild, so a transient throw recovered on the next frame. _MediaResolution resolves once per mediaId and writes ResolvedMedia.missing() into state on error, so the photo shows the corrupt placeholder until navigation rebuilds it. Introduced by PR 162; low severity and user-recoverable, but it is a behaviour the old code had and the new code does not.
- R21 Image cache grows during a long resize drag. decodeTargetWidth rounds up to a 64-pixel bucket and each bucket is a separate ResizeImage cache key, so dragging a window across a wide range holds several decodes of the same photo at once. Not measured; it was the accepted cost of bucketing, and gaplessPlayback now keeps the old frame alive across the swap as well.
- R22 The in-place caption and the Undo toast have still never been seen running on macOS; they are proven by widget tests only. Narrower replacement for the retired risk on the same subject: the toolbar and the footer have now been seen there, and both had real defects that every test passed. Bears on c4.
- R23 The reasoning behind the photo frame fix lives only on this machine. docs/specs/ is gitignored, so the bug spec, its seven binding decisions and the two-blank-path analysis are untracked; a reviewer opening PR 162 sees the diff and the tests but cannot reach why gaplessPlayback and the _MediaResolution holder are both needed.
- R24 Benchmark number 5 (feedScrollFrame) now measures the Today feed's compact log cards, since the day-parity work (PR 167) moved Today off the full-length preview card. The desktop result recorded in docs/specs/research/2026-09-20-android-measurement.md measured the old cards and is not comparable with a future device run on number 5. Numbers 1 and 2, which decide u10, are unaffected. Bears on c2.
- R25 Flutter has no framework path for text wrapping beside a photo. ParagraphConstraints accepts only one width, and no exclusion-zone or float API has shipped or been proposed through Flutter 3.47. Any wrap-beside-photo layout stays app-built (spacer boxes today) with no upstream replacement.
- R26 Open macOS P2 IME bugs in Flutter's delta text input path (Japanese suggestion panel #153065, accent panel #153895) would affect any custom DeltaTextInputClient editor. Flutter's UndoManager engine plugin exists only on iOS.
- R27 Option+Backspace at the start of a paragraph below a table (e.g. '| a | b |\n| - | - |\n\nnext') deletes the last cell's word and the line breaks, giving '| a | |\n| - | - |next'. No hidden bytes are lost, but the lines join and the table stops parsing. The input-method delta path does the same. If the owner wants the table to survive, the only fix is for a word delete from outside a table to change nothing.
- R28 After the PR 181 gestures fixes, every downstream mitosis branch that builds NoteTouchSelection (editor-assembly, consumers, harness, removal, switch-over: lib/features/note_engine/editor/note_editor_view.dart around line 1456) fails to compile until it passes onRequestKeyboard: () => _client.showKeyboard(widget.focusNode).
- R29 When PhotoToolbarLayer hides the bar because the photo starts in the bottom inset band, the engine still sets _photoToolbarShown true (lib/features/note_engine/editor/note_editor_view.dart), so Tab from the selected photo requests focus on the toolbar's detached first-control node instead of falling through. Full fix: the engine's photo-toolbar visibility check should exclude widget.bottomInset.
- R30 log_viewer_reader_test 'the composer writes in the same 688 column in a 1280 window' measures the NoteEditorView widget box, not the engine's text column, so an editor column-cap regression would not fail it (same blind spot as review finding 4, not named by the review).
- R31 The probe-app changes from PR #188's review fixes were never run live: the new state fields, the draft-read delay flag, close?discard=1, open?entry= and the scenario-scoped error log are analyzer-clean and unit-tested only where pure. The first owner harness run may surface probe-side bugs.
- R32 The harness narrow-toolbar mode assumes PhotoToolbar's available width equals the editor's toolbar layer width (notePhotoToolbarLayerKey). If the placement delegate narrows it further, the forced column is still narrow enough; if it widens it, the '…' menu may not appear.
- R33 Several new GB6 and GR8 expectations follow spec text and have never been observed on the app: P2 Cmd+C paste, the macOS selector cases (Option+Up/Down, Ctrl+P/N) and Save being ignored during a delayed draft restore. A failure on the first run may mean a wrong expectation, not an engine bug.
