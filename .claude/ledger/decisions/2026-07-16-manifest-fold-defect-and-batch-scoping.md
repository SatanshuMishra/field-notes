## Context
Root cause of the relaunch failures found: `.mitosis/run.json` was PRETTY-PRINTED (656-line base + 1 JSONL delta). The engine's fold contract requires the base object on ONE compact line (`mitosis.js:3025` writes `JSON.stringify(manifest)`; the write prompt at :3032 says "ONE line ... verbatim"). Verified empirically by replaying `foldRunManifest` (:574-592) against the real bytes: whole-file `JSON.parse` throws on the trailing delta, the line-split fallback parses `lines[0]` == `"{"` and fails, so fold returned **null**. Null fold => `isRelaunch` falsy (:2918) => `reuse={reusable:false}` => full fresh Decompose (:2940-2967) => wholesale overwrite of run.json gated only by `if (!reusable)` (:3023). run.json mtime (Jul 15 19:42) sits inside wf_bfb12095-952's window, confirming that run rewrote it. The ledger's claim that the run "reused 31 MSPs, skipped fresh Decompose" was FALSE — a fresh decompose reproduces the same 31 ids, which looked like reuse. Every relaunch has been paying a full 31-MSP Decompose out of its ~2h window before doing any MSP work.

Separately: the engine exposes NO MSP-filtering input (exhaustive audit of `input.*` — no only/mspIds/include/exclude/targets/maxMsps, and no concurrency cap). Wave width is emergent from the dependency graph; with 14 merged, 8 MSPs were dispatchable, and 8 exceeds one usage window.

## Decision
Batch-scope each relaunch by editing `.mitosis/run.json` out-of-band: keep the currently-merged MSPs (so dependents' prereqs resolve via the in-`runUnit` done-oracle skip) plus one small batch, remove the rest, and serialize the base as ONE compact line. Batch 1 = sound-effects, streak-service, data-management, mood-picker (4 leaf MSPs, no interdependencies, all deps merged); entry-cards excluded so its deterministic add/add conflict stops burning a task graph per run.

## Consequences
Fixing the format makes manifest reuse work for the FIRST time, reclaiming a full Decompose per window — likely the single biggest win. Verified post-edit with the engine's real `foldRunManifest`/`evaluateManifestReuse`: folds, spec hash matches, reuse passes, 14 fast-skip, exactly 4 build, 0 blocked. `clusters` and top-level `parked` are inert (clusters recomputed at :1481-1489; `parked` only appended at :2029) and need no sync. An orphan `park` delta safely no-ops (:564-569), but `ship`/`built` deltas would inject phantom entries (:479-494, :518-535) — never remove an MSP owning one. Reuse normalization DROPS `checkpointRef`/`builtSha` (:1451-1470); harmless as core-providers is merged and gh fast-skips it. `.mitosis/` is gitignored, so backups must live outside it: `scratchpad/run.json.pristine-31msp` is the pristine 31-MSP source of truth. Each later batch must be re-derived FROM the pristine backup + a fresh `gh pr list --state merged`, never trim-on-trim. Risk: a rejected reuse gate silently reverts to fresh-decompose-and-overwrite rather than erroring.
